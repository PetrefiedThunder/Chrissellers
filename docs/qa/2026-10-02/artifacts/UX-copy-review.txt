README.md
1: # chrissellers.com
2: 
3: Personal site and portfolio for Christopher Sellers. A single statically-rendered
4: page: positioning, selected work, career, and contact.
5: 
6: ## Design constraints
7: 
8: The site is a credibility surface — the thing linked from LinkedIn, email
9: signatures, and cold outreach. That drives three rules:
10: 
11: 1. **Zero client JavaScript components.** Every component is a React Server
12:    Component. Content arrives in the HTML, so it survives slow connections,
13:    crawlers, and link-preview bots. The only JS shipped is the React runtime.
14: 2. **Content lives in `src/content/`, not in JSX.** Copy is edited in three data
15:    files; components only lay it out.
16: 3. **No claim the code cannot back up.** Every project states its real status —
17:    including "pre-production" and "built, not shipped."
18: 
19: ## Editing content
20: 
21: | File | What it holds |
22: | --- | --- |
23: | `src/content/profile.ts` | Name, headline, bio, contact links. Also feeds page metadata and the generated OG image. |
24: | `src/content/work.ts` | Projects, split into `featured` and `other`. |
25: | `src/content/career.ts` | Roles, in reverse-chronological order. |
26: 
27: The social preview image (`app/opengraph-image.tsx`) is generated at build time
28: from `profile.ts` — edit the headline and the card follows.
29: 
30: ## Commands
31: 
32: ```bash
33: npm run dev     # local dev server
34: npm run build   # production build
35: npm run lint    # eslint (flat config)
36: npm test        # content validation tests
37: ```
38: 
39: ## Tests
40: 
41: `__tests__/content.test.ts` validates the content files rather than the markup:
42: every project has a status, descriptions are non-trivial, and links are
43: well-formed. This catches a half-finished content edit before it ships. It does
44: **not** check that links resolve — see the note in that file for the trade-off.
45: 
46: ## Stack
47: 
48: Next.js 16 (App Router) · React 18 · TypeScript · Tailwind CSS · Jest
49: 
50: ## Deployment
51: 
52: Live at **https://chrissellers.vercel.app**, deployed automatically from `main`
53: by Vercel's GitHub integration. That integration is configured in the Vercel
54: dashboard, which is why there is no `vercel.json` or `.vercel/` directory here —
55: their absence does not mean the site is unwired.
56: 
57: **`chrissellers.com` is not connected to this project.** It resolves to HostGator
58: shared hosting and returns 403. Until the domain is added to the Vercel project,
59: `siteUrl` in `src/content/profile.ts` must keep pointing at the `.vercel.app`
60: host: it feeds `metadataBase`, so every social preview image is resolved against
61: it, and pointing it at an unserved domain silently breaks every link preview.
